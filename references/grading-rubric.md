# Chaoxing Lab-Report Grading Rubric
Use the assignment prompt first. The rubric below is a default for experimental reports submitted as Word/PDF attachments.
## Score Bands
### 100
Assign 100 only when all of the following are present:
- clear experiment purpose and requirements
- complete environment/equipment description
- complete implementation process, with reproducible code or commands
- relevant result screenshots or figures
- explanation and analysis of those results rather than screenshots alone
- correct conclusion tied to the observed results
- genuine reflection on difficulties, learning, or improvement
- original thought, adaptation, or a meaningful extension
- coherent structure and clean, readable formatting
Do not award 100 if any major evidence item is missing merely because the document is long.
### 80-99
Use 80-99 when the report is substantially complete and correct but has limited deficiencies, such as:
- analysis is brief or partly repetitive
- reflection is generic
- a minor required section is thin
- presentation is mostly clear but uneven
- implementation is correct without notable extension
Near-complete, well-documented work should receive the upper end; basic but valid completion should remain around 80.
### 70-79
Use 70-79 for:
- mostly basic content with limited evidence
- incomplete analysis or weak linkage between code and results
- only one or two required sections substantially developed
- obvious formatting problems or substantial unused template text
- clear signs of copying, superficial AI-like repetition, or content inconsistent with the assignment
Do not use 70-79 for merely concise but complete reports.
### 50-60
Use 50-60 for work that shows little genuine effort:
- only screenshots or only text with no coherent experiment account
- report topic does not match the assigned experiment
- submission is mostly empty or template-only
- wrong student's name/ID or duplicate submission
- requirements are not meaningfully attempted
- content is too simple to demonstrate the requested learning
If the instructor sets a minimum score of 60, use 60 for this band.
## Evidence Checklist
Record these booleans before assigning 100:
| Key | Evidence |
|---|---|
| `purpose` | Experiment objective is explicit |
| `process` | Implementation steps and code/commands are present |
| `results` | Actual run result or output is visible |
| `analysis` | Student explains the result rather than merely displaying it |
| `reflection` | Personal learning or improvement is discussed |
| `originality` | There is original reasoning, adaptation, or extension |
| `formatting` | Report is structured and readable |
## Comments
Every score of 70 or below must receive a specific comment. State what is missing or incorrect and what the student should do next time. Prefer:
> 缺少实际运行结果截图及对结果的分析，请补充代码、运行输出、结果解释和个人总结，下次认真完成作业。
Avoid:
> 做得不好。
For identity or duplicate-file issues, state the observable fact without making an unsupported allegation.
## Consistency
- Apply the same interpretation of evidence across all students.
- Compare similar submissions, not arbitrary page counts.
- If evidence is ambiguous, choose a defensible middle score and note the uncertainty in the working manifest.
- Keep a student's score unchanged unless new evidence or an explicit correction request justifies revision.
